# Task — WB-007 — Privacy guarantees

**Phase**: 15 | **Effort**: 3h | **Deps**: WB-001 | **Spec**: spec/wellbeing.md

## Goal
Lock down privacy invariants in code, not just policy.

## Acceptance criteria
- [ ] `wellbeing_*` tables use per-user-key encryption (AES-256-GCM)
- [ ] Lint rule: no aggregation over `wellbeing_*` columns across users (custom Biome rule)
- [ ] Wisdom layer code (W-001) has assertion: panics if any wellbeing column included
- [ ] Team admin role explicitly cannot read wellbeing tables (RLS policy in Postgres)
- [ ] Audit log entry on every read of wellbeing data, accessible only to user
- [ ] Public commitment in `docs/privacy-commitments.md`
- [ ] Tests: try-and-fail tests proving cross-tenant aggregation throws, admin role denied, etc.
